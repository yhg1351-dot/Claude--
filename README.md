# 경주 수학여행 미션 앱

6학년 수학여행(불국사 · 경주월드 · 국립경주박물관)에서 모둠별로 퀴즈와 사진 미션을 수행하고, 교사가 제출 내용을 확인하는 웹앱입니다.
설치 없이 휴대폰 브라우저에서 열립니다.

- 학생 화면: `index.html` — 모둠 코드(예: `6101` = 6학년 1반 1모둠, `6906` = 9반 6모둠)로 접속
- 교사 화면: `teacher.html` — 이메일/비밀번호 로그인 후 현황 · 답변 · 사진 확인, CSV 내려받기, 전체 삭제

## 안정성을 위해 넣은 장치

| 상황 | 대응 |
|---|---|
| 관광지에서 신호가 끊김 | 제출은 먼저 폰에 저장되고, 연결되면 자동으로 순서대로 전송 (앱을 닫았다 열어도 유지) |
| 사진 용량이 큼 | 올리기 전에 폰에서 긴 변 2000px, 약 600KB 이하로 압축(졸업 앨범용 화질). 미션당 최대 6장. 교사 화면 목록에는 약 30KB짜리 미리보기만 내려받아 전송량을 아낌 |
| 전송 실패 | 2초 → 4초 → … → 최대 60초 간격으로 자동 재시도. 이미 올라간 사진은 다시 올리지 않음 |
| 같은 미션을 두 번 제출 | 서버에서 모둠+미션 기준으로 덮어쓰기 (중복 저장 없음) |
| 한 모둠 코드로 여러 폰이 접속 | 모둠원 누구나 들어와 일정·미션을 볼 수 있음(보기 모드). 제출은 '대표 폰으로 정하기'를 누른 한 대만. 대표 폰이 5분간 신호가 없으면 다른 폰이 이어받을 수 있고, 교사가 즉시 해제도 가능 |
| 폰이 바뀜 | 서버에 있는 제출 내역을 새 폰이 이어받음. 이전 폰에 남은 미전송 제출도 나중에 접수됨 |
| 앱 파일 자체가 안 열림 | 서비스 워커가 앱 파일을 폰에 캐시해 신호가 약해도 화면이 열림 |
| 대표 폰 해제 | 교사가 '해제'하면 서버가 토큰을 새로 발급해 옛 폰의 신호가 통하지 않고, 옛 폰은 보기 모드로 바뀜. 학생이 버튼으로 다시 대표가 될 수는 있음 |
| 외부인의 사진 업로드 | 최근 3일 안에 활동한 실제 모둠 폴더에만 올릴 수 있고 덮어쓰기는 불가. 모둠 코드는 편집본의 학년·반·모둠 수에 맞아야 접속됨 |
| 첫 화면이 안 열림 | 서버 설정 읽기는 10초 안에 응답이 없으면 캐시·기본 파일로 넘어감. 8초 넘게 로딩되면 '다시 열기·처음부터 다시 열기' 버튼 표시. 화면 그리기 오류가 나면 빈 화면 대신 오류 내용과 초기화 버튼이 있는 복구 카드 표시 |
| 외부인이 사진을 봄 | 사진은 비공개 저장소에 있고, 로그인한 교사만 짧게 유효한 링크로 열람 |

## 도장과 완주 인증서

- 교사 화면의 제출 카드에서 **도장 찍기 / 지우기**를 누르면 학생 도장판에 바로 표시됩니다. 퀴즈 정답은 자동으로 도장이 찍힙니다.
- 모든 미션에 도장이 찍히면 학생 앱에 **완주 인증서**가 자동으로 열립니다(모둠당 한 번, 이후에는 홈의 버튼으로). 인증서 아래에는 **쿠우쿠우 입장권**이 붙어 있어 2일차 점심에 보여 주면 됩니다. 학생 앱은 1분마다, 그리고 화면으로 돌아올 때 도장 상태를 받아옵니다.
- 이 기능은 `supabase/add-stamps.sql`을 한 번 실행해야 동작합니다.

## 홈 화면에 앱 추가

- 학생 앱 첫 화면과 홈 아래에 **📲 홈 화면에 앱 추가** 버튼이 있습니다.
- 안드로이드 크롬·삼성 인터넷은 브라우저가 주는 설치 창을 그대로 엽니다. 설치 창이 준비되지 않은 폰(이미 설치했거나, 크롬이 조건을 통과시키지 않은 경우)에는 브라우저별로 직접 추가하는 순서를 보여 줍니다.
- 아이폰은 사파리 공유 버튼 → '홈 화면에 추가' 순서를 안내합니다. 카카오톡 등 앱 안 브라우저에서는 버튼이 나타나지 않습니다(먼저 기본 브라우저로 열도록 안내).
- 교사 화면에도 같은 기능이 있습니다. 로그인 화면과 도구 탭의 **📲 이 폰에 교사 화면 설치** 버튼으로 학생 앱과 별개의 아이콘이 생기며, 로그인은 유지됩니다.
- 학생 앱과 교사 앱은 설치 범위가 각각 `index.html`, `teacher.html` 로 나뉘어 있어 한 폰에 둘 다 설치할 수 있습니다. (범위가 겹치면 크롬이 두 번째 앱을 '이미 설치됨'으로 보고 설치 창을 열지 않습니다.) 이전 범위로 설치한 앱이 남아 있으면 지우고 다시 설치하세요.

## 1. 미션 내용 수정

**교사 화면 → 편집 탭**에서 일정(날짜·시간·순서), 장소(이름·아이콘·안내문·안내 이미지), 미션(퀴즈·글·사진), 반/모둠 수를 고치고 "저장"을 누르면 학생 앱에 바로 반영됩니다. 편집 내용은 Supabase에 저장되며, 아래 `supabase/add-editor.sql`을 한 번 실행해 두어야 합니다.

서버에 저장된 편집본이 없을 때는 `data/missions.json` 파일의 내용을 사용합니다. 이 파일에는 일정, 반/모둠 수, 장소별 미션이 들어 있습니다.
GitHub 웹에서 파일을 열어 연필 아이콘으로 수정하고 저장(Commit)하면 1~2분 뒤 앱에 반영됩니다.

- 미션 유형: `choice`(객관식, `options`와 정답 번호 `answer`는 0부터), `text`(짧은 글), `photo`(사진, `maxPhotos`와 설명 요청 `caption`)
- `classes`: 반 번호와 반별 모둠 수. 모둠 코드는 `학년 + 반 + 모둠 2자리`로 만들어집니다.
- 쉼표와 따옴표를 지우지 않도록 주의하세요. 저장 전 [JSON 검사기](https://jsonlint.com)에 붙여넣어 확인하면 안전합니다.

## 2. GitHub Pages로 배포

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
2. 기본 브랜치에 푸시하면 `.github/workflows/pages.yml`이 자동으로 배포합니다. (처음 실행 시 Pages를 자동으로 켜려고 시도합니다)
3. 주소는 `https://<계정>.github.io/<저장소 이름>/` 입니다. QR 코드로 만들어 학생에게 나눠 주세요.
4. 저장소가 비공개(private)면 무료 계정에서는 Pages를 쓸 수 없습니다. 공개 저장소여도 학생 데이터는 저장소에 저장되지 않습니다.

## 3. Supabase 연결 (사진 · 제출 저장)

Supabase 값을 넣기 전까지 앱은 **데모 모드**로 동작합니다. 데모 모드에서는 제출 내용이 그 기기 브라우저 안에만 저장되므로, 흐름을 미리 확인할 때 쓰세요.
(교사 화면 비밀번호는 `js/config.js`의 `localTeacherPassword`, 기본값 `1234`)

1. [supabase.com](https://supabase.com)에서 무료 프로젝트를 만듭니다. (Region: Northeast Asia (Seoul) 권장)
2. **SQL Editor**에 `supabase/schema.sql` 내용을 전부 붙여넣고 **Run** 합니다. 이 파일 하나가 최신 상태 전체이며 여러 번 실행해도 안전합니다. (`supabase/fix-*.sql`, `add-*.sql`, `update-*.sql` 은 예전에 단계별로 적용하던 파일로, 모두 `schema.sql` 에 포함되어 있습니다. 새로 만드는 프로젝트에는 쓰지 마세요. 이미 쓰던 프로젝트도 `schema.sql` 을 다시 실행하면 같은 결과입니다.)
3. **Authentication → Users → Add user**로 교사 계정(이메일/비밀번호)을 만듭니다. "Auto Confirm User"를 켭니다. 교사 19명이 공용 계정 하나를 써도 되고 각자 만들어도 됩니다.
   - 그 이메일을 `js/config.js`의 `teacherEmail`에 넣으면 교사 화면에서 비밀번호("교사 코드")만 입력하면 됩니다. 비밀번호는 6자 이상이어야 하며, Authentication → Users에서 언제든 바꿀 수 있습니다.
4. **Project Settings → API**에서 `Project URL`과 `anon public` 키를 복사해 `js/config.js`에 넣습니다.
   ```js
   supabaseUrl: "https://xxxx.supabase.co",
   supabaseAnonKey: "eyJ...",
   ```
5. 푸시하면 끝. 학생 화면에서 "데모 모드" 문구가 사라지면 연결된 것입니다.

무료 플랜 참고
- 저장 1GB, 월 전송 5GB. 모둠 54개 × 사진 미션 4개 × 6장 × 약 500KB ≈ 650MB. 사진 미션 수를 6개 이하로 유지하세요.
- 서버 함수를 고친 뒤에는 `supabase/schema.sql` 을 다시 실행하면 됩니다. 앱 코드가 먼저 배포된 뒤(푸시 후 2~3분) 실행하세요. 학생 앱은 새 함수가 없으면 예전 방식으로 동작하지만, 반대로 함수만 먼저 바꾸면 예전 앱이 설정을 못 읽을 수 있습니다.
- 점검용 GitHub Actions(diag)를 돌리면 6999 모둠과 사진이 생깁니다. 여행 전 '학생 데이터 전체 삭제'로 정리하세요.
- 1주일 이상 접속이 없으면 프로젝트가 일시정지됩니다. 여행 1~2주 전에 만들고, 전날 교사 화면에 한 번 접속해 두세요. (정지되면 대시보드에서 Restore)
- Authentication → Rate Limits 는 기본값이면 충분합니다 (학생은 로그인을 쓰지 않음).

## 4. 여행 전 점검 목록

- [ ] 아이폰·안드로이드 각각에서 모둠 코드로 접속하고 사진 미션을 제출해 본다.
- [ ] 비행기 모드로 제출한 뒤 켰을 때 자동 전송되는지 확인한다.
- [ ] 두 번째 폰에서 같은 코드로 접속하면 막히는지, 교사 화면 "해제" 후 들어가지는지 확인한다.
- [ ] 교사 화면에서 사진이 보이고 CSV가 내려받아지는지 확인한다.
- [ ] 여행 후 교사 화면 → 도구 → "학생 데이터 전체 삭제"로 사진과 답변을 지운다.

## 5. 로컬에서 열어 보기

```
npx serve .
```
브라우저에서 `http://localhost:3000` 을 열면 데모 모드로 동작합니다.

## 파일 구성

```
index.html            학생 화면
teacher.html          교사 화면
data/missions.json    일정 · 반/모둠 · 미션 (여기만 고치면 됨)
js/config.js          Supabase 주소/키, 잠금 시간, 사진 압축 설정
js/app.js             학생 화면 동작
js/teacher.js         교사 화면 동작
js/sync.js            전송 대기열 · 재시도
js/backend.js         Supabase / 데모 모드 연동
js/store.js           폰 저장소(IndexedDB)
js/image.js           사진 압축
sw.js                 오프라인 캐시
supabase/schema.sql   Supabase 테이블 · 함수 · 보안 규칙
.github/workflows/pages.yml   GitHub Pages 자동 배포
```
